# [ADR-viewer] Repository viewer distribution and read-only local server

- **Status**: Accepted
- **Date**: 2026-10-22
- **Deciders**: @minjae
- **Involved Components/Capabilities**: `packages/devkit-viewer/` (Python package and `frontend/`),
  `.devkit/generated.toml` (`CAP-GEN-tracked-artifacts`), `CAP-DLV-human-interaction`, `CAP-INT-mcp-services`,
  autohub `modules/hub-ui/`

---

## 1. Context & Problem Statement

devkit owns the viewer source (decided in Backlog, `SPEC-repository-viewer`). devkit is a Python monorepo: consumers
install its distributions from Git subdirectories at a pinned commit, so `uv` builds them from source on every
install. The viewer is a Svelte 5 component that two hosts need: devkit's own local server and autohub's SvelteKit
UI. The decision chooses the distribution, where the built assets come from, and how autohub receives the component.

The viewer reads through a `RepositoryDataSource` (`info`, `tree(path, ref)`, `blob(path, ref)`). devkit's server must
provide it for several local repositories at once, show work that lives on `plan-` and `dev-` branches
(`ADR-milestone-documents`: the base shows only merged state), stay safe as a local web server, and decide whether
the viewer takes part in approvals.

`ADR-source-bound-review-reports-and-explicit-lifecycle-approval` later required an optional readable view of
immutable, expiring proposal-review reports without committing translations, which the original all-reads-through-Git
restriction excluded.

---

## 2. Decision Drivers

- Installing devkit from Git never needs Node or npm network access.
- One source for both hosts; no registry publication.
- People who do not run the viewer do not install its assets (the lazily loaded `mermaid` alone is several MB).
- One `devkit` executable (`ADR-mount-under-the-devkit-command-line`).
- Do not reintroduce what autohub removed in `0d8c05f`: runtime loading of an externally hosted Custom Element bundle
  named by an HTTPS URL and SHA-256 in a Git-ignored local file, downloaded at deployment build time, and published as
  a separate operation.
- No path outside a registered repository is reachable.
- Any branch is readable without switching a checkout or fetching.
- No new runtime dependency where the standard library suffices.
- No daemon (`ARCH-01-introduction-and-goals` §3.4).
- Each approval keeps one path (`CAP-DLV-human-interaction`, `CAP-INT-mcp-services`).
- Repositories pinning different `devkit-spec` versions are all readable.

---

## 3. Considered Options

### Distribution

- **Inside `devkit-spec`, behind an extra** (rejected by `ADR-viewer-distribution-and-frontend-build`): an extra adds
  dependencies only, so the built assets would ship in every `devkit-spec` install.
- **`devkit-catalog`** (rejected by `ADR-viewer-distribution-and-frontend-build`): holds data-only content bundles;
  runtime Python code belongs elsewhere (`MS-catalog-and-context-scaling` non-goals).
- **A separate `devkit-viewer` distribution** (selected by `ADR-viewer-distribution-and-frontend-build`): mounted
  through `devkit.commands`, installed only by those who run it; needs no `devkit-spec` code, because the browser
  parses the documents.

### Built assets

- **Build at wheel build time** (rejected by `ADR-viewer-distribution-and-frontend-build`): every Git install would
  need Node and npm network access.
- **Download a release artifact at run time** (rejected by `ADR-viewer-distribution-and-frontend-build`): a
  publication step and network access at run time.
- **Commit the built assets as a tracked generated artifact** (selected by
  `ADR-viewer-distribution-and-frontend-build`): `devkit generated check` refuses stale assets; Node is needed only to
  change the frontend.

### autohub consumption

- **npm registry** (rejected by `ADR-viewer-distribution-and-frontend-build`): no publication.
- **`git+https` dependency** (rejected by `ADR-viewer-distribution-and-frontend-build`): npm installs only a
  repository's root package, and the viewer lives in a subdirectory.
- **Runtime-loaded Custom Element bundle** (rejected by `ADR-viewer-distribution-and-frontend-build`): what autohub
  removed in `0d8c05f`.
- **Vendored `npm pack` tarball** (selected by `ADR-viewer-distribution-and-frontend-build`): compiled into autohub's
  own build, so none of the removed runtime-loading machinery returns.

### Reads

- **Working tree files** (rejected by `ADR-read-only-local-server-over-git-refs`): shows uncommitted edits, but needs
  path traversal guards and cannot show other branches.
- **Git objects at a ref** (selected by `ADR-read-only-local-server-over-git-refs`): `git ls-tree` and `git cat-file`
  reach only paths in the ref's tree, read any local branch, and never touch a checkout.
- **An exact generation route for proposal-review artifacts through the local shared adapter** (added by
  `ADR-local-immutable-proposal-review-view`, alongside the Git routes).

### Server stack

- **Starlette or a similar framework** (rejected by `ADR-read-only-local-server-over-git-refs`): new dependencies for
  a GET-only local server.
- **Standard library `http.server`** (selected by `ADR-read-only-local-server-over-git-refs`): `ThreadingHTTPServer`
  with GET handlers.

### Registration

- **A user-level configuration file** (rejected by `ADR-read-only-local-server-over-git-refs`): a new file format to
  maintain.
- **Command options** (selected by `ADR-read-only-local-server-over-git-refs`).

### Parsing

- **Run each repository's `devkit spec list --format json`** (rejected by `ADR-read-only-local-server-over-git-refs`):
  needs each repository's own environment.
- **Parse in the browser, as autohub does** (selected by `ADR-read-only-local-server-over-git-refs`).

### Approvals

- **Record answers from the viewer** (rejected by `ADR-read-only-local-server-over-git-refs`): allowed for `record`
  answers by `CAP-DLV-human-interaction` §1, but the waiting agent sees them only at its next `devkit workflow next`,
  and the server would need write access, a committer and a token.
- **Grant integration approval from the viewer** (rejected by `ADR-read-only-local-server-over-git-refs`): the
  `integration_integrate` authority is bound to a request in the memory of the stdio MCP process the host started.
- **Read-only, approvals out** (selected by `ADR-read-only-local-server-over-git-refs`).

## 4. Decision Outcome

### Distribution and frontend

- **Python**: `packages/devkit-viewer/`, distribution `devkit-viewer`, import package `devkit_viewer`, depending on
  `devkit-agt` for `devkit.core.cli`. Entry point `devkit.commands` `viewer`; the command is `devkit viewer serve`.
  (ADR-viewer-distribution-and-frontend-build)
- **Frontend**: one npm project under `packages/devkit-viewer/frontend/` with two outputs from one source: a Svelte
  component library (`svelte-package`: the viewer moved from autohub, `SddViewer`, `KnowledgeViews`, `documents.ts`,
  the `RepositoryDataSource` interface, plus the roadmap view; `svelte` is a peer dependency), and a Vite single-page
  app that imports the library, adds the repository switcher, and builds into `src/devkit_viewer/static/`.
  (ADR-viewer-distribution-and-frontend-build)
- **Assets**: the app build output is committed and registered in `.devkit/generated.toml` as a generated artifact
  whose inputs are the frontend sources and lockfile; Development verifies that the build is reproducible from the
  lockfile before relying on `devkit generated check`. (ADR-viewer-distribution-and-frontend-build)
- **autohub**: keeps `RepositoryView`, its Git browser (`FileTreeTable`, `FileBlobViewer`) and its run and decision
  panels (`SddExecution`, `SddProposals`, `SddRunLinks`), and passes its existing GitHub-backed data source to the
  library component. It commits the `npm pack` tarball under `modules/hub-ui/vendor/`, depends on it with
  `file:vendor/<name>.tgz`, pins its integrity in `package-lock.json` and documents the source commit and rebuild
  steps, as for `vendor/api-codegen.md`. Adopting the tarball is autohub's own change, made after a devkit commit
  carries the library. (ADR-viewer-distribution-and-frontend-build)
- **Checks**: the `just` recipes gain the frontend (lint, type check, unit tests) through `scripts/`; `just smoke`
  checks that the installed wheel serves its assets. (ADR-viewer-distribution-and-frontend-build)

### Server

- **Process**: `devkit viewer serve [--repo PATH]... [--scan DIR] [--port N]` runs in the foreground until
  interrupted. `--repo` is repeatable; `--scan DIR` registers each direct child that is a Git repository with
  `.devkit/config.toml`. stdout carries one sentinel, `[VIEWER: url=<url> repos=<n>]`; refusals are advisories with
  stable codes (an unknown or duplicate repository ID, no repository registered, port in use); access logs appear only
  under `-v`. (ADR-read-only-local-server-over-git-refs)
- **Repository ID**: the directory name; two registered repositories with the same name are refused.
  (ADR-read-only-local-server-over-git-refs)
- **API**, GET only, the `tree` and `blob` shapes matching autohub's so `httpDataSource` works unchanged:
  `/api/repos`, `/api/repos/{id}/info` (the checked-out branch as `default_branch`), `/api/repos/{id}/refs` (local
  branches), `/api/repos/{id}/tree?path=&ref=`, `/api/repos/{id}/blob?path=&ref=`. `refs` is an optional member of
  `RepositoryDataSource`; without it the roadmap view reads the default branch only.
  (ADR-read-only-local-server-over-git-refs)
- **Git routes**: ordinary routes read Git objects at a ref, resolved with `git rev-parse --verify --end-of-options`;
  remote-only branches are not read and nothing is fetched. (ADR-read-only-local-server-over-git-refs,
  ADR-local-immutable-proposal-review-view)
- **Proposal-review route**: the all-reads-through-Git restriction no longer holds for one exact generation route for
  proposal-review artifacts, read through each registered repository's configured local shared adapter. No remote
  adapter, arbitrary path, write, regeneration, sweep, approval or automatic server start is added. It renders escaped
  Markdown source with source SHA, language and expiry; no report HTML or script executes.
  (ADR-local-immutable-proposal-review-view)
- **Safety**: binds `127.0.0.1` only, refuses a request whose `Host` header is not the loopback address or `localhost`
  at the bound port (DNS rebinding), sends no CORS headers, and has no write endpoint.
  (ADR-read-only-local-server-over-git-refs, ADR-local-immutable-proposal-review-view)
- **Roadmap**: milestones by status (`done` and `dropped` behind a history toggle), `depends_on` order and readiness,
  and members (proposals and specs naming the milestone) on the default branch and, through `refs`, on local `plan-`
  and `dev-` branches. (ADR-read-only-local-server-over-git-refs)
- **Out**: the working tree's uncommitted content, open workflow requests, and every write.
  (ADR-read-only-local-server-over-git-refs)

## 5. Consequences

- **Positive**: Git installs need no Node; one source serves both hosts; the viewer never changes what an agent or a
  person approves, or where.
- **Negative / Risks**: the repository gains its first Node toolchain, for frontend contributors only. The library's
  props and `RepositoryDataSource` become an interface autohub depends on; the vendored tarball pins a commit, so a
  breaking change reaches autohub only when it refreshes the tarball, and the release note of such a change names it.
  Refreshing the tarball in autohub is a manual step, documented beside the tarball. Uncommitted edits are not
  visible; a person sees their document after committing it (showing the working tree is a possible follow-up).
  Reading every activity branch is bounded by the number of local branches; the roadmap view reads them on demand.
- **Proposal reviews**: the viewer imports the shared local read contract in addition to core/advisory. Reading never
  extends TTL and expired reports require Host publication. Rendering is deliberately a readable source view;
  host-specific links and native form presentation require separate observation.
- **Follow-ups**: `AGENTS.md` and the README list the distribution, and the layering test covers `devkit_viewer`.
