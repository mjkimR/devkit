# Shared foundation and distribution support

`devkit-core` owns `devkit_core.core`: filesystem and Git primitives, deadlines, frontmatter,
plugin loading, extension dispatch and logging. `devkit_core.base` owns shared errors and SDK-free
MCP contracts and never imports `devkit_core.core`. The package depends only on
`devkit-advisory` and PyYAML and can be installed without the CLI or any application wheel.

`devkit_dist.features.project` owns project configuration, installation receipts and execution
binding behavior. Its models own receipt, template and presentation contracts; repositories
read configuration, receipts and live invocation state; services resolve configured presentation;
use cases coordinate CLI/MCP invocation. `devkit_dist.base` holds shared distribution contracts;
`devkit_dist.adapters.cli` owns the common CLI boundary: `devkit_cli` (`CAP-CLI-agent-cli-toolkit`) bound to devkit. Import generic primitives from `devkit_core` directly.

## Modules

| Module | Purpose |
| --- | --- |
| `devkit_core.base.errors` / `devkit_dist.base.errors` | `DevkitCoreError`, an `AdvisoryError`, and its subclasses with their codes: `FrontmatterError` (`FRONTMATTER_INVALID`, `INPUT_ERROR`), `ReceiptError` (`RECEIPT_INVALID`, `MAINTENANCE`, fix: restore the receipt from version control, then `devkit sync`), `ConfigError` (`CONFIG_INVALID`, `INPUT_ERROR`, target `.devkit/config.toml`; the base of each area's `<AREA>_CONFIG_INVALID` table error), `ArgumentError` (`ARGUMENT_INVALID`, `INPUT_ERROR`; every semantic argument check of every command; also a `devkit.advisory.ArgumentError`, which owns the code), `UnsafePathError` (`PATH_UNSAFE`, `INPUT_ERROR`), `DevkitRootNestedError` (`DEVKIT_ROOT_NESTED`, `INPUT_ERROR`; a `.devkit/` below the top level of a Git work tree whose top level has none, see `devkit_dist.features.project.repositories.project`), `AssetFileError` (`ASSET_FILE_INVALID`, `MAINTENANCE`; a missing file is `AUTO` with the fix `devkit sync`), `GitError` (`GIT_FAILED`, `MAINTENANCE`; also carries `command`, `returncode` and `stderr`), `DeadlineExceededError` (`DEADLINE_EXCEEDED`, `DEFER`; a `Deadline` ran out, carries `what` and `seconds`), `LockHeldError` (`LOCK_HELD`, `DEFER`; a `DeadlineExceededError`: another process held a `file_lock` past the allowed wait), `LockUnsupportedError` (`LOCK_UNSUPPORTED`, `BLOCKED`; no `fcntl.flock` on the platform), `CommandPluginError` (`COMMAND_PLUGIN_INVALID`, `MAINTENANCE`; a `devkit.commands` entry point that cannot be used, see `ARCH-05-3-command-plugins`) and `HarnessCommandUnavailableError` (`HARNESS_COMMAND_UNAVAILABLE`, `INTERACTION`, exit `2`; a harness command name such as `devkit rules` or `devkit run` that no installed package provides, so `devkit-agt` is missing; `fix`: `HARNESS_INSTALL_FIX`). The module also holds the source-explicit requirements `DIST_REQUIREMENT` and `AGT_REQUIREMENT` (full Git requirements, never a bare package name), `HARNESS_INSTALL_FIX` (the directive that adds `devkit-agt` to a project or a tool installation, shared with the `HARNESS_ENGINE_MISSING` notice of `devkit_dist.features.distribution`) and `extra_install_fix(extra)` (the `[FIX]` of a missing `search` or `mcp` extra: the extra on the `devkit-agt` requirement when the project depends on it, else on the `devkit-dist` one, never both). None is a `ValueError`. A module that knows more re-raises with its own code or fields; otherwise the CLI boundary renders them as they are. |
| `devkit_core.core.frontmatter` | The one YAML frontmatter grammar. `locate(text)` returns the block's character offsets (for byte-preserving rewrites), `parse(text)` returns `Frontmatter(data, body, body_line)`, `load_header(yaml)` parses a header alone. The grammar accepts a UTF-8 BOM, CRLF line endings, trailing whitespace on delimiters, and a `---` or `...` closer. It rejects an unclosed block, invalid YAML (including an impossible date such as `2024-02-30` and nesting too deep to parse), non-mapping YAML, non-string top-level keys and duplicate keys, all as `FrontmatterError`. |
| `devkit_dist.features.project.repositories.receipt` | Strict typed reader for `.devkit/installation.json` (`RECEIPT_PATH`), the well-known project paths `CONFIG_PATH`, `MANAGED_PATH` (`.devkit/managed`), `OVERRIDES_PATH` (`.devkit/overrides`) and `AGENTS_FILE` (the root `AGENTS.md`), and the guidance block markers `GUIDANCE_START`/`GUIDANCE_END`, shared so a rule can measure the block that `devkit sync` writes. `load_receipt(root)` returns `None` only when the file is absent; a file (or `.devkit/` directory) that cannot be read, malformed or too deeply nested JSON, duplicate keys, schema violations and unsafe paths raise `ReceiptError`. `parse_receipt(raw)` validates bytes or text the same way. `Receipt.assets(kind=...)`, `AssetRecord.files(suffix)`, `Receipt.file(path)`, `Receipt.file_hash(path)` and `FileRecord.matches(data)` cover the common queries. `verified_asset_file(root, item, receipt, asset, source_root=None)` is the one check applied before importing receipt-listed code (rules and gates): the path must stay inside `root` (a path that cannot be resolved, such as a symlink loop, is unsafe), a recorded file must match its SHA-256, only a project override under `.devkit/overrides/` may lack a record (it is then used as is; any other unrecorded file is refused), a file that cannot be read is refused, and for a Git snapshot a file absent from `root` is taken from `source_root` only when it matches its record; failures raise `AssetFileError` (`ASSET_FILE_INVALID`) with a `devkit sync` or `devkit override create` fix. `verified_asset_packages(root, receipt, kind, source_root=None) -> (packages, errors)` turns every `kind` asset into one `PluginPackage`: each listed file is taken relative to the asset's source directory (the `.devkit/managed/<bundle>/` or `.devkit/overrides/<bundle>/` prefix removed, then the directory common to all the asset's paths), every module file among them (`plugin_module_name`: test files excluded) goes through `verified_asset_file`, so one package may mix overrides, managed copies and snapshot working-tree copies, and the package's `root` is the asset's directory under the managed root and its `sources` hold the verified bytes, so loading compiles exactly what was checked (never a file changed since, never a bytecode cache). An asset with an unusable file yields no package; each such file is one `AssetFileError` (one unreadable file never aborts other assets). Rules and gates both find their receipt-listed code with it, and no module is skipped for its name (a `_helpers.py` is a module like any other). |
| `devkit_core.core.paths` | `normalize_relpath(value, canonical=False)`, `is_safe_relpath(value)` and `resolve_within(root, rel)` (symlink-aware containment; a path that cannot be resolved, such as a symlink loop, is `UnsafePathError` too). Absolute paths, `..`, empty values, `.` and backslash escapes are rejected; a backslash inside a file name is accepted. |
| `devkit_core.core.files` | `atomic_write_bytes(path, data, mode=None)` and `atomic_write_text(path, text, mode=None)` (UTF-8, no newline translation) replace a file atomically: a temporary file in the same directory is written, `fsync`ed and given its permission bits, then `os.replace`s the target, and the directory is synced, best effort (a failed directory sync after the replacement is not raised); a failure before the replacement leaves the target unchanged. `mode=None` keeps the existing regular file's bits, else gives a new file `0o666` less the process umask (`0o644` under `022`, `0o600` under `077`), as `open` would. The replacement is a new inode: a hard link to the old file keeps the old content, and the owner, ACLs and extended attributes are not carried over. Missing parent directories are created. A symlink at `path` is replaced, never written through; a caller that means the link's target resolves and confines the path first (`resolve_within`). POSIX only. `remove_empty_tree(path) -> list[Path]` removes the directory `path` when it and every directory beneath it hold no file, all or nothing: a file at any depth keeps the whole tree, and a symlink counts as a file (never followed, never removed). It returns the removed directories deepest first, `path` last, and `[]` when `path` is missing, a symlink, not a directory or holds a file; a directory that cannot be listed raises `OSError` before anything is removed. The tree is listed first and then removed through directory descriptors that never follow a link, only the directories the listing found: a directory swapped for a symlink between the two passes raises `OSError` without being followed, a `path` that is no longer the listed directory removes nothing, and a file created meanwhile raises `OSError` leaving its parents in place (so the result is all or nothing only while nothing else changes the tree). |
| `devkit_core.core.git` | `run_git(cwd, *args, input=None, timeout=DEFAULT_TIMEOUT, index=None, deadline=None) -> bytes`; raises `GitError` with the exit status and stderr. `index` sets `GIT_INDEX_FILE` for the call. `deadline` (a `Deadline`) replaces `timeout` (a `timeout` other than `DEFAULT_TIMEOUT` passed with it is a `ValueError`, a programming error, as in `file_lock`): an expired deadline starts no Git, Git gets the time left, and a Git still running when it runs out is killed; both raise `deadline.exceeded("git <subcommand>")` (`DEADLINE_EXCEEDED` unless the deadline has an error factory), every other failure stays `GitError`. Git inherits the environment (so a hook's `GIT_DIR`/`GIT_INDEX_FILE` apply) with `LC_ALL=C` (its messages are never localized) and `GIT_TERMINAL_PROMPT=0` (it fails instead of prompting) on top; without `input` its standard input is `/dev/null`, so it never consumes the caller's input (a hook's ref list) or waits on a prompt. `DEFAULT_TIMEOUT` (60 seconds) is the one Git timeout every area uses. Decode paths with `errors="surrogateescape"`. |
| `devkit_core.core.deadline` | `Deadline(seconds, *, error=None)`: a point in monotonic time several steps share, each taking the time left. `remaining()` (seconds, zero or negative once passed), `expired()`, `exceeded(what)` (builds the expiry error: `error(what, seconds)` when a factory is given, else `DeadlineExceededError` with the message `<what> exceeded the deadline of <seconds>s`) and `check(what)` (raises it once expired). A caller with its own code passes its factory, so `check`, `run_git(..., deadline=)` and `file_lock(..., deadline=)` raise that code directly; or it catches `DeadlineExceededError` and re-raises. |
| `devkit_core.core.locks` | `file_lock(path, *, shared=False, timeout=None, deadline=None, what=None)`: a context manager holding an exclusive or shared `fcntl.flock` on the lock file `path` for the block (Linux and macOS; `LockUnsupportedError` elsewhere; released when the process dies, so none goes stale; not for network file systems). `path` is created with mode `0o600` when missing; its directory must exist. It is opened with `O_NOFOLLOW`: a symlink, a directory or another non-regular file is `UnsafePathError` and is never locked through; other file system failures raise `OSError`. Without `timeout` or `deadline` it blocks until the lock is free; with one (not both: `ValueError`, a programming error, as in `run_git`) it polls every `POLL_INTERVAL` (0.01 s), at least once, so `timeout=0` never waits. When the wait runs out it raises `deadline.exceeded(what)` for a deadline with an error factory, else `LockHeldError` (`LOCK_HELD`, `what` defaulting to `waiting for the lock on <path>`). The project lock of `devkit_dist.features.distribution` and the clone lock of `devkit gate` are built on it. |
| `devkit_core.core.plugins` | Plugin packages: rules and gates are directories of Python modules. `PluginPackage(key, root, modules, sources={})` maps each dotted module name relative to the package (`""` for `__init__.py`, `"sub.helpers"` for `sub/helpers.py`) to the exact file to run; `key` names the package (its module name is `<namespace>_<sha256 prefix of key>`), `root` is what failures name, and `sources` maps a dotted name to the source bytes compiled in place of reading its file (the file still names the module). `PluginPackage.from_directory(dir)` collects every module of a directory: each `.py` file recursively except files under `tests/`, `test_*.py`, `*_test.py`, `__pycache__` and hidden entries (`plugin_module_name(relative)`); `plugin_modules(pairs)` builds a mapping and `check_plugin_modules(modules)` rejects non-identifier names and a module with two files (`ValueError`). `load_subclasses(packages, base, namespace=..., validate=None) -> PluginLoad` imports each package through its own `sys.meta_path` finder that resolves `<package>.<dotted>` only to the mapped files (a module cannot import an unlisted file; relative imports, also lazy ones at run time, work), imports every module (packages before their submodules), and instantiates every concrete `base` subclass defined in one of them, each class once, in module then definition order (`LoadedPlugin`: defining module `path`, `instance`, `package`). Loading is atomic per package: a failure removes the package's modules and finder and is one `PluginFailure(path, message, fix)` naming the package root; a loaded package keeps its finder installed. Plugin code always runs from source: a `__pycache__` `.pyc` beside a plugin file is never read, and none is written. `iter_plugin_packages(dir) -> (packages, failures)` scans a plugin directory (`--rules-dir`): each immediate subdirectory not starting with `_` or `.` (and not `tests`) is one package, and a `.py` file directly in it is a failure whose `fix` moves it into `<dir>/<name>/`. |
| `devkit_dist.features.project.repositories.project` | Two roots: the *repository root* (the Git work tree's top level, used for Git operations) and the *devkit root* (the directory holding `.devkit/`, used for configuration, the receipt and managed files). Inside a Git work tree they are the same directory; a `.devkit/` below the top level is not a project of its own. `find_project_root(start)` returns the devkit root: inside a Git work tree its top level, except that when the top level has no `.devkit/` but `start` or a directory between it and the top level has one (a project in `~/notes` while the home directory is a dotfiles repository, or a legacy `packages/app/.devkit` in a monorepo), it raises `DevkitRootNestedError` (`DEVKIT_ROOT_NESTED`, `INPUT_ERROR`, naming both directories, fix: make the nested directory a Git repository of its own, or move its `.devkit/` to the top level), since resolving to the top level would read no configuration, receipt or managed rules and a check would pass vacuously; outside one (or without Git) the nearest directory with `.devkit/`, a walk that never reaches the user's home directory or a directory above it, so a stray `~/.devkit` does not claim the directories under it (`start` itself is always considered), else `start`; a `start` that cannot be resolved (a symlink loop) is `UnsafePathError`; this is the default of `-w/--workspace-root` for every command. `require_devkit_root(root, param='--workspace-root')` returns `root` resolved when it is outside Git or the top level of its work tree; for a directory below the top level it raises `DevkitRootNestedError` when that directory or one between it and the top level has `.devkit/` and the top level has none, else `ArgumentError` (`ARGUMENT_INVALID`, whose `fix` names the top level only when the top level has `.devkit/`, and otherwise says to make the directory a Git repository of its own or omit the option); an explicit `-w` of the distribution, `devkit rules`, `devkit workflow` and plugin commands goes through it (`devkit gate` and `devkit worktree` take any directory inside the work tree and use its top level). `require_git_toplevel(start)` returns the resolved top level of the Git work tree containing `start` and raises `GitError` (`GIT_FAILED`, `INPUT_ERROR`, target `--workspace-root`, Git's stderr in the message) when Git ran and refused it (outside a work tree, or a repository Git will not use under `safe.directory`); when Git produced no exit status (not installed, timed out) `run_git`'s `GitError` (`MAINTENANCE`) passes through unchanged; `git_toplevel(start)` returns it or `None`. `read_toml(path, display=None)` parses a TOML file (`None` when it does not exist; an unreadable or invalid file, or one in an unreadable directory, raises `ConfigError` naming `display`); `read_project_config(root)` reads `.devkit/config.toml` (`CONFIG_PATH`) with it, a missing file being `{}`. `config_table(value, context, error)` returns a table or raises the area's `ConfigError` subclass `error` (`config <context>: expected a table`). |
| `devkit_core.core.logs` | `get_logger(name)`, the logger every devkit module takes (`get_logger(__name__)`), and `ROOT` (`"devkit"`). Importing it adds a `NullHandler` to the `devkit` logger once, so records never reach Python's last-resort handler; all independent package namespaces share this logging root. |
| `devkit_dist.features.project.services.config_template` | The types a tool describes its `[tool.<name>]` tables with for the commented template of `.devkit/config.toml` (`CAP-DIST-sync-and-transactions`). `TemplateKey(name, default=None, help="", kind="", example=None)`: `default` as the reader applies it, or `None` when unset by default, which then shows `example` (marked `example;`, its `help` saying what applies while unset); `kind` names the accepted values, derived from the value when empty. `TemplateTable(keys, path=(), help="", array=False)`: `path` below `[tool.<name>]`, `array` an array of tables (none by default, values are examples). `render_tool_template(name, tables)` renders them as `devkit config template` does (prose `##`, header and keys `#`); `uncomment(text)` removes one `#` per line, as an editor does, so a tool's tests can check that its template reads back as its defaults; `check_tables(value)` raises `ValueError` for anything that cannot render (paths and key names not bare TOML keys or listed twice, a key with neither default nor example, a value TOML cannot hold). |
| `devkit_dist.adapters.cli` | The command-line plumbing every command group uses; the contract it implements is `ARCH-08-1-agent-output`. The output names below are `devkit_cli`'s, re-exported; `BOUNDARY` (`boundary`) is `devkit_cli.Boundary("devkit")`, so the variables are `DEVKIT_QUIET`, `DEVKIT_VERBOSE` and `DEVKIT_STRICT` and `-v` prints the `devkit` logger hierarchy, with the unexpected-error traceback logged on `devkit_dist.adapters.cli`. Options: `workspace_option(help=...)` (`-w/--workspace-root`, default `None`), `FORMAT_OPTION` (`--format text\|json`, case-insensitive), `output_options` (`-q/--quiet`, `-v/--verbose`, `--strict`). Roots: `resolve_root(value)` (a given value goes through `existing_directory` and then `require_devkit_root`, so a missing directory or one below the top level of a Git work tree is `ArgumentError` and a nested `.devkit/` is `DevkitRootNestedError`; without a value, `find_project_root(cwd)`), `existing_directory(value, param)` (an empty or whitespace-only value, a path that cannot be resolved such as a symlink loop, and a path that is not a directory are `ArgumentError`; an empty `-w` is never read as the current directory). Boundary: `boundary` / `boundary(json_only=True)` applies the output options while the command runs (the command function never sees the three parameters; under verbose it attaches the `[INFO]` stderr log handler and logs the traceback of an exception it reports as `UNEXPECTED_ERROR`), renders an error on stderr or, in JSON mode, only as `{"error": {...}}` on stdout (with the warnings and notices passed to `echo_notices` before the failure under `notices`), then exits with its `exit_code`; `Reported` is an error whose result is already on stdout (rendered on stderr in text mode only). In JSON mode no advisory is rendered on stderr, since the JSON object carries them all. Before the command runs it makes `sys.stdout` and `sys.stderr` UTF-8 with `backslashreplace`, so output bytes never depend on the locale and a character UTF-8 cannot encode (a lone surrogate from a `surrogateescape`-decoded path) is written as its `\uXXXX` escape. A `BrokenPipeError` (the reader closed stdout, as in `devkit ... \| head`) ends the command quietly: stdout is redirected to the null device, no advisory is printed, and the exit code is `2` (the result was not delivered). Output: `is_json`, `echo_json(obj)` (one object, `indent=2`, `ensure_ascii=False`: text stays UTF-8, and a lone surrogate becomes a `\uXXXX` escape through the stream's `backslashreplace`, so the JSON is always valid; size budgets such as `playbook search --max-bytes` measure this serialization), `echo_notices(notices)` (warnings and notices on stderr after the result; notices skipped under quiet; nothing in JSON mode), `exit_on_warnings(notices)` (under strict, exit `1` when any notice is a `WARNING`). Exit: `highest_exit_code` / `exit_on_problems(problems)` (render collected problems, except in JSON mode, and exit with the highest code), `report_exit_code(problems)` / `exit_on_problems(problems, report=True)` (status and show commands: exit `1` when the report lists any problem). Settings: `resolve_output(quiet, verbose, strict)` (combines the flags with `DEVKIT_QUIET`, `DEVKIT_VERBOSE`, `DEVKIT_STRICT` as specified in `ARCH-08-1-agent-output`; quiet with verbose is `ArgumentError`), `output_settings()` (the current `OutputSettings(quiet, verbose, strict, json)`, `json` set by `boundary` when stdout is JSON; all off outside a command). |

Foundation primitives are exported from `devkit_core.core`; frontmatter functions remain under
`devkit_core.core.frontmatter`. Project configuration and receipt behavior are exposed by
`devkit_dist.features.project`; CLI helpers live under `devkit_dist.adapters.cli`.

Application features use the foundation without changing its dependency direction (`ARCH-05-2-components`).

Foundation errors (`DevkitCoreError`, `ArgumentError`, `FrontmatterError`, `UnsafePathError`, `GitError`,
`DeadlineExceededError`, `LockHeldError`, `LockUnsupportedError`) live in `devkit_core.base.errors`.
Receipt, asset, configuration, project-root and command-plugin errors stay in `devkit_dist.base.errors`.
