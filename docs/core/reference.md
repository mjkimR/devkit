# devkit.core

Shared foundation of the `devkit` modules: one implementation of what several
modules must agree on, so their behavior cannot drift apart. It carries no
document or workflow model; it is the SDD-agnostic base the other modules build on.
Part of the `devkit` package; it depends on `pyyaml` and `devkit.advisory`, and
`devkit.core.cli` (not imported by `devkit.core` itself) also on `click`.

## Modules

| Module | Purpose |
| --- | --- |
| `devkit.core.errors` | `DevkitCoreError`, an `AdvisoryError`, and its subclasses with their codes: `FrontmatterError` (`FRONTMATTER_INVALID`, `INPUT_ERROR`), `ReceiptError` (`RECEIPT_INVALID`, `MAINTENANCE`, fix: restore the receipt from version control, then `devkit sync`), `ConfigError` (`CONFIG_INVALID`, `INPUT_ERROR`, target `.devkit/config.toml`; the base of each area's `<AREA>_CONFIG_INVALID` table error), `ArgumentError` (`ARGUMENT_INVALID`, `INPUT_ERROR`; every semantic argument check of every command), `UnsafePathError` (`PATH_UNSAFE`, `INPUT_ERROR`), `AssetFileError` (`ASSET_FILE_INVALID`, `MAINTENANCE`) and `GitError` (`GIT_FAILED`, `MAINTENANCE`; also carries `command`, `returncode` and `stderr`). None is a `ValueError`. A module that knows more re-raises with its own code or fields; otherwise the CLI boundary renders them as they are. |
| `devkit.core.frontmatter` | The one YAML frontmatter grammar. `locate(text)` returns the block's character offsets (for byte-preserving rewrites), `parse(text)` returns `Frontmatter(data, body, body_line)`, `load_header(yaml)` parses a header alone. The grammar accepts a UTF-8 BOM, CRLF line endings, trailing whitespace on delimiters, and a `---` or `...` closer. It rejects an unclosed block, non-mapping YAML, non-string top-level keys and duplicate keys. |
| `devkit.core.receipt` | Strict typed reader for `.devkit/installation.json` (`RECEIPT_PATH`), and the well-known project paths `CONFIG_PATH`, `MANAGED_PATH` (`.devkit/managed`) and `OVERRIDES_PATH` (`.devkit/overrides`). `load_receipt(root)` returns `None` only when the file is absent; malformed JSON, duplicate keys, schema violations and unsafe paths raise `ReceiptError`. `parse_receipt(raw)` validates bytes or text the same way. `Receipt.assets(kind=...)`, `AssetRecord.files(suffix)`, `Receipt.file(path)`, `Receipt.file_hash(path)` and `FileRecord.matches(data)` cover the common queries. `verified_asset_file(root, item, receipt, asset, source_root=None)` is the one check applied before importing receipt-listed code (rules, gates, workflow plugin checks): the path must stay inside `root`, a recorded file must match its SHA-256 (an unrecorded project override is used as is), and for a Git snapshot a file absent from `root` is taken from `source_root` only when it matches its record; failures raise `AssetFileError` (`ASSET_FILE_INVALID`) with a `devkit sync` or `devkit override create` fix. `verified_asset_files(root, receipt, kind, suffix=".py", source_root=None) -> (paths, errors)` applies it to every file of every `kind` asset (`entrypoints` then `paths`, ending in `suffix`, without duplicates) and returns the usable paths and the `AssetFileError`s; rules, gates and workflow plugin checks all find their receipt-listed files with it, and no listed file is skipped for its name (a `_helpers.py` loads like any other). |
| `devkit.core.paths` | `normalize_relpath(value, canonical=False)`, `is_safe_relpath(value)` and `resolve_within(root, rel)` (symlink-aware containment). Absolute paths, `..`, empty values, `.` and backslash escapes are rejected; a backslash inside a file name is accepted. |
| `devkit.core.git` | `run_git(cwd, *args, input=None, timeout=DEFAULT_TIMEOUT) -> bytes`; raises `GitError` with the exit status and stderr. `DEFAULT_TIMEOUT` (60 seconds) is the one Git timeout every area uses. Decode paths with `errors="surrogateescape"`. |
| `devkit.core.plugins` | `load_subclasses(files, base, namespace=..., validate=None) -> PluginLoad` imports plugin files under stable module names. It instantiates the concrete subclasses defined in each file, atomically per file, and never leaves a failed module in `sys.modules`. `iter_plugin_files(dir)` scans a directory and skips `_`/`.` names; it is the only place a name filter applies (`load_subclasses` loads every file it is given). |
| `devkit.core.project` | `find_project_root(start)`: the nearest `.devkit/` directory up to the Git top level, else the Git top level, else `start`; this is the default of `-w/--workspace-root` for the distribution, `devkit rules` and `devkit workflow` commands (`devkit gate` uses the Git top level). `require_git_toplevel(start)` returns the resolved top level of the Git work tree containing `start` and raises `GitError` (`GIT_FAILED`, `INPUT_ERROR`, target `--workspace-root`) outside one; `git_toplevel(start)` returns it or `None`. `read_toml(path, display=None)` parses a TOML file (`None` when it does not exist; an unreadable or invalid file raises `ConfigError` naming `display`); `read_project_config(root)` reads `.devkit/config.toml` (`CONFIG_PATH`) with it, a missing file being `{}`. `config_table(value, context, error)` returns a table or raises the area's `ConfigError` subclass `error` (`config <context>: expected a table`). |
| `devkit.core.cli` | The command-line plumbing every command group uses: `workspace_option(help=...)` (`-w/--workspace-root`, default `None`), `FORMAT_OPTION` (`--format text\|json`, case-insensitive), `resolve_root(value)` (an existing directory, else `find_project_root(cwd)`; a missing directory is `ArgumentError`), `existing_directory(value, param)`, `is_json`, `echo_json(obj)` (one object, `indent=2`, `ensure_ascii=False`), `boundary` / `boundary(json_only=True)` (renders an error on stderr and, in JSON mode, as `{"error": {...}}` on stdout, then exits with its `exit_code`), `Reported` (an error whose JSON result is already on stdout), `highest_exit_code` / `exit_on_problems(problems)` (render collected problems and exit with the highest code), and `report_exit_code(problems)` / `exit_on_problems(problems, report=True)` for status and show commands (exit `1` when the report lists any problem, whatever its own code). |

Public names are exported from `devkit.core` (frontmatter functions through
their module, `devkit.core.frontmatter`).

## Used by

`devkit.rules`, `devkit.workflow`, `devkit.gate` and `devkit.distribution`.
`devkit.core` imports only `devkit.advisory`, for its error base class.
