# devkit.core

Shared foundation of the `devkit` modules: one implementation of what several
modules must agree on, so their behavior cannot drift apart. It carries no
document or workflow model. It depends on `pyyaml` and `devkit.advisory` (for its
error base class); `devkit.core.cli` (not imported by `devkit.core` itself) also
on `click`.

## Modules

| Module | Purpose |
| --- | --- |
| `devkit.core.errors` | `DevkitCoreError`, an `AdvisoryError`, and its subclasses with their codes: `FrontmatterError` (`FRONTMATTER_INVALID`, `INPUT_ERROR`), `ReceiptError` (`RECEIPT_INVALID`, `MAINTENANCE`, fix: restore the receipt from version control, then `devkit sync`), `ConfigError` (`CONFIG_INVALID`, `INPUT_ERROR`, target `.devkit/config.toml`; the base of each area's `<AREA>_CONFIG_INVALID` table error), `ArgumentError` (`ARGUMENT_INVALID`, `INPUT_ERROR`; every semantic argument check of every command), `UnsafePathError` (`PATH_UNSAFE`, `INPUT_ERROR`), `AssetFileError` (`ASSET_FILE_INVALID`, `MAINTENANCE`; a missing file is `AUTO` with the fix `devkit sync`), `GitError` (`GIT_FAILED`, `MAINTENANCE`; also carries `command`, `returncode` and `stderr`) and `CommandPluginError` (`COMMAND_PLUGIN_INVALID`, `MAINTENANCE`; a `devkit.commands` entry point that cannot be used, see [Command Plugins](../architecture/command-plugins.md)). None is a `ValueError`. A module that knows more re-raises with its own code or fields; otherwise the CLI boundary renders them as they are. |
| `devkit.core.frontmatter` | The one YAML frontmatter grammar. `locate(text)` returns the block's character offsets (for byte-preserving rewrites), `parse(text)` returns `Frontmatter(data, body, body_line)`, `load_header(yaml)` parses a header alone. The grammar accepts a UTF-8 BOM, CRLF line endings, trailing whitespace on delimiters, and a `---` or `...` closer. It rejects an unclosed block, invalid YAML (including an impossible date such as `2024-02-30` and nesting too deep to parse), non-mapping YAML, non-string top-level keys and duplicate keys, all as `FrontmatterError`. |
| `devkit.core.receipt` | Strict typed reader for `.devkit/installation.json` (`RECEIPT_PATH`), the well-known project paths `CONFIG_PATH`, `MANAGED_PATH` (`.devkit/managed`), `OVERRIDES_PATH` (`.devkit/overrides`) and `AGENTS_FILE` (the root `AGENTS.md`), and the guidance block markers `GUIDANCE_START`/`GUIDANCE_END`, shared so a rule can measure the block that `devkit sync` writes. `load_receipt(root)` returns `None` only when the file is absent; a file (or `.devkit/` directory) that cannot be read, malformed or too deeply nested JSON, duplicate keys, schema violations and unsafe paths raise `ReceiptError`. `parse_receipt(raw)` validates bytes or text the same way. `Receipt.assets(kind=...)`, `AssetRecord.files(suffix)`, `Receipt.file(path)`, `Receipt.file_hash(path)` and `FileRecord.matches(data)` cover the common queries. `verified_asset_file(root, item, receipt, asset, source_root=None)` is the one check applied before importing receipt-listed code (rules, gates, workflow plugin checks): the path must stay inside `root` (a path that cannot be resolved, such as a symlink loop, is unsafe), a recorded file must match its SHA-256, only a project override under `.devkit/overrides/` may lack a record (it is then used as is; any other unrecorded file is refused), a file that cannot be read is refused, and for a Git snapshot a file absent from `root` is taken from `source_root` only when it matches its record; failures raise `AssetFileError` (`ASSET_FILE_INVALID`) with a `devkit sync` or `devkit override create` fix. `verified_asset_files(root, receipt, kind, suffix=".py", source_root=None) -> (paths, errors)` applies it to every file of every `kind` asset (`entrypoints` then `paths`, ending in `suffix`, without duplicates) and returns the usable paths and the `AssetFileError`s (one per unusable file, so one unreadable file never aborts the rest); rules, gates and workflow plugin checks all find their receipt-listed files with it, and no listed file is skipped for its name (a `_helpers.py` loads like any other). |
| `devkit.core.paths` | `normalize_relpath(value, canonical=False)`, `is_safe_relpath(value)` and `resolve_within(root, rel)` (symlink-aware containment; a path that cannot be resolved, such as a symlink loop, is `UnsafePathError` too). Absolute paths, `..`, empty values, `.` and backslash escapes are rejected; a backslash inside a file name is accepted. |
| `devkit.core.git` | `run_git(cwd, *args, input=None, timeout=DEFAULT_TIMEOUT) -> bytes`; raises `GitError` with the exit status and stderr. Git inherits the environment (so a hook's `GIT_DIR`/`GIT_INDEX_FILE` apply) with `LC_ALL=C` (its messages are never localized) and `GIT_TERMINAL_PROMPT=0` (it fails instead of prompting) on top; without `input` its standard input is `/dev/null`, so it never consumes the caller's input (a hook's ref list) or waits on a prompt. `DEFAULT_TIMEOUT` (60 seconds) is the one Git timeout every area uses. Decode paths with `errors="surrogateescape"`. |
| `devkit.core.plugins` | `load_subclasses(files, base, namespace=..., validate=None) -> PluginLoad` imports plugin files under stable module names. It instantiates the concrete subclasses defined in each file, atomically per file, and never leaves a failed module in `sys.modules`. `iter_plugin_files(dir)` scans a directory and skips `_`/`.` names; it is the only place a name filter applies (`load_subclasses` loads every file it is given). |
| `devkit.core.project` | `find_project_root(start)`: the nearest `.devkit/` directory up to the Git top level, else the Git top level, else `start`; outside a Git work tree (or without Git) the walk never reaches the user's home directory or a directory above it, so a stray `~/.devkit` does not claim the directories under it (`start` itself is always considered); a `start` that cannot be resolved (a symlink loop) is `UnsafePathError`; this is the default of `-w/--workspace-root` for the distribution, `devkit rules` and `devkit workflow` commands (`devkit gate` uses the Git top level). `require_git_toplevel(start)` returns the resolved top level of the Git work tree containing `start` and raises `GitError` (`GIT_FAILED`, `INPUT_ERROR`, target `--workspace-root`, Git's stderr in the message) when Git ran and refused it (outside a work tree, or a repository Git will not use under `safe.directory`); when Git produced no exit status (not installed, timed out) `run_git`'s `GitError` (`MAINTENANCE`) passes through unchanged; `git_toplevel(start)` returns it or `None`. `read_toml(path, display=None)` parses a TOML file (`None` when it does not exist; an unreadable or invalid file, or one in an unreadable directory, raises `ConfigError` naming `display`); `read_project_config(root)` reads `.devkit/config.toml` (`CONFIG_PATH`) with it, a missing file being `{}`. `config_table(value, context, error)` returns a table or raises the area's `ConfigError` subclass `error` (`config <context>: expected a table`). |
| `devkit.core.logs` | `get_logger(name)`, the logger every devkit module takes (`get_logger(__name__)`), and `ROOT` (`"devkit"`). Importing it adds a `NullHandler` to the `devkit` logger once, so records never reach Python's last-resort handler; it lives here because `devkit` is a namespace package shared with `devkit-advisory` and has no `__init__`. |
| `devkit.core.cli` | The command-line plumbing every command group uses; the contract it implements is [Agent-First Output](../architecture/agent-output.md). Options: `workspace_option(help=...)` (`-w/--workspace-root`, default `None`), `FORMAT_OPTION` (`--format text\|json`, case-insensitive), `output_options` (`-q/--quiet`, `-v/--verbose`, `--strict`). Roots: `resolve_root(value)` (an existing directory, else `find_project_root(cwd)`; a missing directory is `ArgumentError`), `existing_directory(value, param)` (an empty or whitespace-only value, a path that cannot be resolved such as a symlink loop, and a path that is not a directory are `ArgumentError`; an empty `-w` is never read as the current directory). Boundary: `boundary` / `boundary(json_only=True)` applies the output options while the command runs (the command function never sees the three parameters; under verbose it attaches the `[INFO]` stderr log handler and logs the traceback of an exception it reports as `UNEXPECTED_ERROR`), renders an error on stderr or, in JSON mode, only as `{"error": {...}}` on stdout (with the warnings and notices passed to `echo_notices` before the failure under `notices`), then exits with its `exit_code`; `Reported` is an error whose result is already on stdout (rendered on stderr in text mode only). In JSON mode no advisory is rendered on stderr, since the JSON object carries them all. Before the command runs it makes `sys.stdout` and `sys.stderr` UTF-8 with `backslashreplace`, so output bytes never depend on the locale and a character UTF-8 cannot encode (a lone surrogate from a `surrogateescape`-decoded path) is written as its `\uXXXX` escape. A `BrokenPipeError` (the reader closed stdout, as in `devkit ... \| head`) ends the command quietly: stdout is redirected to the null device, no advisory is printed, and the exit code is `2` (the result was not delivered). Output: `is_json`, `echo_json(obj)` (one object, `indent=2`, `ensure_ascii=False`: text stays UTF-8, and a lone surrogate becomes a `\uXXXX` escape through the stream's `backslashreplace`, so the JSON is always valid; size budgets such as `playbook search --max-bytes` measure this serialization), `echo_notices(notices)` (warnings and notices on stderr after the result; notices skipped under quiet; nothing in JSON mode), `exit_on_warnings(notices)` (under strict, exit `1` when any notice is a `WARNING`). Exit: `highest_exit_code` / `exit_on_problems(problems)` (render collected problems, except in JSON mode, and exit with the highest code), `report_exit_code(problems)` / `exit_on_problems(problems, report=True)` (status and show commands: exit `1` when the report lists any problem). Settings: `resolve_output(quiet, verbose, strict)` (combines the flags with `DEVKIT_QUIET`, `DEVKIT_VERBOSE`, `DEVKIT_STRICT` as specified in [Agent-First Output, section 6](../architecture/agent-output.md#6-verbosity-and-strictness); quiet with verbose is `ArgumentError`), `output_settings()` (the current `OutputSettings(quiet, verbose, strict, json)`, `json` set by `boundary` when stdout is JSON; all off outside a command). |

Public names are exported from `devkit.core` (frontmatter functions through
their module, `devkit.core.frontmatter`).

Every other `devkit` module except `devkit.advisory` builds on it ([layering](../architecture/overview.md#1-system-mission--core-modules)).
