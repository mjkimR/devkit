# devkit in this repository

This repository uses `devkit` to install agent assets from versioned bundles:
skills, subagents, instructions, playbooks, workflows, governance rules and
commit gates. Everything devkit writes is derived from installed packages and
the Git-tracked selection in `.devkit/config.toml`; the receipt
`.devkit/installation.json` records exactly what was deployed.

## Contracts

1. **Load context once per bundle.** Before working with a bundle's assets, run
   `uv run devkit get-context <bundle>` once in the current agent context. It
   returns the bundle's constitution and its instruction headers with paths.
   Read an instruction body only when its header matches the current work.
   Reload only after the context was lost (compaction, new conversation).
2. **Never edit generated copies.** `.devkit/managed/` and the projections under
   `.claude/`, `.agents/` and `.codex/` are regenerated by `devkit sync`, which
   refuses to run over a modified managed file. Change the source bundle, or
   create an override with `devkit override create <bundle>:<asset>`.
3. **Selection lives in `.devkit/config.toml`.** Installing a package only makes
   its bundle available. `devkit add <bundle>[:<preset>]` selects it or adds a
   preset, and syncs; `devkit remove <bundle>` deselects. `devkit` and
   `advisory` are selected by default; `<bundle> = false` under `[presets]`
   opts out. A plain `devkit sync` converges the workspace to the selection.
4. **Playbooks are explicit.** Ordinary tasks never search playbooks. Use the
   `devkit-playbook` skill only when the user invokes it for the current task.
5. **Rules and gates run as code.** `devkit rules check` loads synchronized
   rules without flags; `devkit gate` runs synchronized gates at commit time.
   Configure them in `[rules]` and `[gates]` of `.devkit/config.toml`, never by
   editing the managed file.
6. **Commit the receipt with the change.** After `devkit sync`, commit
   `.devkit/installation.json` with the change that required it. Snapshot gates
   (`devkit rules check --staged`, `--ci`) trust the committed receipt and fail
   when a managed rule no longer matches it.

## Instructions in this bundle

- `consumption`: these contracts in full, with the commands.
- `resource-kinds`: which asset kind to author for a given need.
- `in-repo-bundle`: shipping this repository's own assets as a bundle it
  installs from itself.
- `devkit-run`: running tests, linters and type checks through `devkit run`,
  and wrapping recipes with it.

Read `resource-kinds` and `in-repo-bundle` before adding a rule, skill,
playbook, instruction, subagent, workflow or gate to this repository.
