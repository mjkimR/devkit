# Adaptive Development

Advance the agreed product by its next useful discovery, research, implementation or verification action.
Adaptive development can stay the project's approach; product size or elapsed time never forces graduation.

- Read this context once per agent context; use `/adaptive-dev` for product work and resume.
- Selecting this bundle changes assets only: never implicitly switch approach, remove SDD assets or reopen SDD history.
- Before authoring a document, read `uv run devkit get-context docs` and the relevant writing instructions.
- Keep independent build, lint, test and actual-usage checks; report skipped or unavailable evidence as unverified.
- Keep the main agent focused on decomposition, delegation, integration and final validation; actively delegate useful separable work.
- Decide implementation choices inside the agreed goal yourself; return changes to the goal or its constraints to the user.
- Only the Host writes current facts to project-owned `.devkit/adaptive-dev.md`, when useful and before pausing or handing off.
- Product-support roles return evidence, never commit and keep index and HEAD unchanged; swarm workers commit only under an explicit assignment grant.
- Swarm agents follow their caller's workflow and authority, including SDD; selecting them grants no approach or host-setting change.
- Use the project's ordinary Git and host permissions; no per-change SDD Unit, approval, envelope or immutable experiment history is required.
- The delegating agent SHOULD record assignments and verify returns with `uv run devkit adaptive assignment`; if a command cannot record, keep the manual procedure and report assignments as unrecorded.
