# devkit in this repository

This repository uses `devkit` to install agent assets from versioned bundles:
skills, subagents, instructions, playbooks, guidance, documents and host hooks,
and the rule, gate and workflow assets whose engines come with `devkit-agt`.
Everything devkit writes is derived from installed packages and the Git-tracked
selection in `.devkit/config.toml`; the receipt `.devkit/installation.json`
records exactly what was deployed.

## Contracts

1. **Load context once per bundle.** Before working with a bundle's assets, run
   `uv run devkit get-context <bundle>` once in the current agent context. It
   returns the bundle's constitution and its instruction headers with paths.
   Read an instruction body only when its header matches the current work.
   Reload only after the context was lost (compaction, new conversation).
2. **Never edit generated copies.** `.devkit/managed/` and the projections under
   `.claude/`, `.agents/` and `.codex/` are regenerated by `devkit sync`, which
   refuses to run over a modified managed file. Change the source bundle, or
   create an override with `devkit override create <bundle>:<asset>`.
3. **Selection lives in `.devkit/config.toml`.** Installing a package only makes
   its bundle available. `devkit add <bundle>[:<preset>]` selects it or adds a
   preset, and syncs; `devkit remove <bundle>` deselects. Bundles that declare
   `auto_select` are selected by default (`devkit list` shows them);
   `<bundle> = false` under `[presets]` opts out. A plain `devkit sync`
   converges the workspace to the selection.
4. **Playbooks are explicit.** Ordinary tasks never search playbooks. Use the
   `devkit-playbook` skill only when the user invokes it for the current task.
5. **Commit the receipt with the change.** After `devkit sync`, commit
   `.devkit/installation.json` with the change that required it.
