# Idea Incubation

Develop the agreed product through the next useful discovery, research, implementation or verification action.
Incubation can remain the project's approach; product size or elapsed time never forces graduation.

- Read this context once per agent context; use `/incubate` for idea discovery, iterative implementation and resume.
- Before product work, inspect `uv run devkit config show` and require effective `configuration.development.approach` to be `incubation`; if inspection fails or the approach is SDD, stop product work and report the shared configuration action.
- Selecting this bundle changes assets only; never switch approach, remove SDD assets or reopen existing SDD history implicitly.
- Before document authoring, read `uv run devkit get-context docs` and the relevant writing instructions.
- Keep independent build, lint, tests and actual-usage checks; report skipped or unavailable evidence as unverified.
- Only the coordinator writes current facts to project-owned `.devkit/incubation.md`, when useful and before pausing or handing off; optional roles return evidence and never commit.
- Make implementation choices inside the agreed goal autonomously; return changes to that goal or its constraints to the user.
- Use the project's ordinary Git and host permissions; no per-change SDD Unit, approval, envelope or immutable experiment history is required.
