# Product clarification

1. Identify what is missing for the next useful action: intended users, problem, constraints, representative usage or signs that the first version helps.
2. Reuse known answers; ask only the missing decision in ordinary language, with a recommended option when evidence supports one.
3. If the direction is open, compare a small set of candidates by the user's goal, trade-offs and assumptions worth testing.
4. Label a user decision, an agent recommendation and an unverified assumption separately; never infer user approval from the absence of a reply.
5. Choose the narrowest first version that exercises a representative flow; a complete backlog or architecture is not an entry requirement.
6. If a concrete uncertainty blocks that version, begin bounded research or implementation evidence instead of extending a fixed questionnaire.
7. Reopen only the question a working result invalidates; do not restart a formal planning lifecycle.

Example: for a goal of sharing a household list, reuse a stated mobile-web constraint and ask whether two people need simultaneous edits before choosing storage. Do not ask the user to restate the platform or produce a complete feature backlog.
