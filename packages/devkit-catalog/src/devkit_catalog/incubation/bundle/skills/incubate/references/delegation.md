# Optional support

1. Work inline when a separate context would add no useful evidence; no iteration requires all roles.
2. Assign `product-clarifier` for candidate users/problems, alternatives and missing product questions.
3. Assign `incubation-researcher` for evidence about one concrete decision, or an experiment with an explicit bounded write area.
4. Assign `usage-reviewer` to exercise a representative flow in an assigned test environment against stated expectations.
5. Pass one goal, absolute read boundaries, any permitted write boundary, source/artifact identity, expected output and the host permissions already granted.
6. Name the installed role contract by absolute path and state whether the host provides native isolation or emulates it.
7. On an emulated host, use explicit boundaries and compare actual source/index/HEAD before and after; never claim a native guarantee.
8. Wait for each role you started; validate its evidence and failure conditions before folding it into retained choices.
9. Reject out-of-scope writes or invented authority as evidence and report the actual state to the coordinator; do not reset or discard another actor's work.
10. Only the coordinator updates `.devkit/incubation.md`; role selection grants neither a product decision nor commit authority.

The return contains `status` (completed, needs_input or failed), summary, source/artifact identity, observations with evidence and failure conditions, recommendation, assumptions and unverified areas. An experiment also returns its actual changed paths, commands and outcomes. No SDD envelope is required.
