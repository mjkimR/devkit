# Technical Plan: `SPEC-namespace-roadmap` Per-namespace milestones under the namespace docs root

## 1. Constitution & Invariant Review

- `ADR-namespace-milestone-roots` (accepted at handoff) supersedes in part `ADR-roadmap-and-milestones-ledger`: the
  clause "Milestones are global; per-namespace roadmaps are deferred until a repository needs them" and the
  global-root wording of the archive clause. Every other clause of the ledger stands; no further ADR is needed.
- `CAP-DOCS-namespaces` 3.2 and 3.3 are unchanged rules: membership by path and repository-wide identity are what
  the change relies on. 3.4 gains `roadmap/` in the directories the rules treat like `docs/`.
- `CAP-GOV-spec-rules` Milestone validation contract changes from "namespace roadmap locations are invalid" to the
  two-root rule; the `RULE-spec-format` scope list gains the namespace roadmap.
- `CAP-DLV-proposal-planning` `--milestone` changes from "one existing global MS ID" to a milestone at either root.
- `ARCH-05-2-components`: `devkit-spec` already imports `devkit_docs.features.documents`; reading the namespace
  registry in `roadmap.py` adds no new package edge. `devkit-dist` and the viewer are untouched.

## 2. Architecture Overview & Impact

Four code locations change; every other location in the Planning inventory is kind- or status-based and stays.

| Component | Change |
| --- | --- |
| `devkit_docs.features.documents.models.kinds` | `Kind.MILESTONE` row: `format_scope=FormatScope.EVERY_ROOT`, so `RULE-spec-format` `_directories` adds `docs/packages/<name>/roadmap` per registered namespace (its `_archive/` is reached by the recursive walk). `PROPOSAL` stays `GLOBAL`. |
| `devkit_docs.features.governance.usecases.id_convention` | `_targets`: `valid = milestone_path_valid(living_path(path, namespaces=registered), status)` for every docs root (drops the `docs_root == "docs"` condition); the `_PATH_REMEDIATIONS[Kind.MILESTONE]`, the inline `path_issue` and the uncovered-milestone `path_issue` name both roots. |
| `devkit_docs.features.governance.usecases.spec_format` | The milestone status and `created_at` checks are guarded by `living_path(path, namespaces=registered).startswith("docs/roadmap/")`; the registered namespaces are passed down from the caller that already loads them. |
| `devkit_spec.features.proposals.usecases.roadmap.milestone_id` | Validates `milestone_path_valid(living_path(found[0].path, namespaces=read_docs_config(root).namespaces), found[0].status)`; the `ArgumentError` message reads "must name one existing milestone at the global or a namespace roadmap root" and the fix names `devkit docs list milestone --all-namespaces`. |

`milestone_path_valid` keeps its global regex (Non-Goal 4). `living_path` with the registered namespaces leaves an
unregistered `docs/packages/<name>/roadmap/` path unchanged, so it fails the global regex and stays misplaced (AC-02,
AC-05).

Remediation wording (one sentence, both roots):
`Rename or move the file to MS-{slug}.md under docs/roadmap/ or docs/packages/<name>/roadmap/ of a registered namespace for planned/active, or under its _archive/ for done/dropped (the ID is the file stem), then run ...`.

## 4. Error Handling & Edge Cases

- An unregistered `docs/packages/<name>/roadmap/` file: `living_path` returns it unchanged, the regex fails, reported
  as misplaced by `RULE-id-convention` and refused by `--milestone`; `RULE-spec-format` does not scan it by default
  (it is not a registered docs root).
- A malformed `[tool.docs]` table fails `--milestone` with `DOCS_CONFIG_INVALID` as every command reading it does
  (`CAP-DOCS-namespaces` 3.1 rule 7); no new handling.
- Duplicate identity across roots (the same `MS-` ID at the global root and a namespace root) stays the existing
  duplicated-identity error of `RULE-id-convention` and the existing `--milestone` refusal (`index.canonical` finds
  more than one).
- The `status` of a milestone outside `{planned, active, done, dropped}` is treated as unknown for placement (as
  today) and reported by `RULE-spec-format`.
